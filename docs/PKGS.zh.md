# PKGS 个人知识与认知成长指南

[简体中文](PKGS.zh.md) · [English](PKGS.en.md) · [Grove README](../README.md)

## 定位

PKGS（Personal Knowledge & Growth System）是一套以个人长期成长为目标的方法。它以个人积累的知识和思考记录为基础，可以借助人与 AI 协作，把思想探索、知识管理、专业研究、独立判断、内容创造和认知反思连起来。最终希望增长的是理解、研究、判断和表达的能力。一个念头可以暂时停留在原处，等日后读到新材料再继续。

用纸笔、普通 Markdown 或现有笔记工具就能开始。Grove 是这套方法在 DeepSeek Harness 和 Obsidian 中的一种轻量实践。下文描述的是方法，你可以按自己的主题和节奏选用。[项目缘起与总体设计讨论](https://chatgpt.com/s/t_6af7c6721c0081919564b556c5e5dcd3)

## 理论如何落到日常

| 借鉴 | 可以怎么做 |
| --- | --- |
| 个人知识管理 | 把读到的内容用自己的话解释，再找一个可以应用或检验它的场景。 |
| 卡片笔记法（Zettelkasten） | 给可独立讨论的想法一条记录，并写清它与其他想法的关联。保留有完整语境的文章和原始资料。 |
| 元认知 | 问自己为什么相信当前判断，它依赖哪些假设，什么会让自己改主意。 |
| 自我调节学习 | 先确定想弄明白什么，探索中留意方法是否奏效，回顾后调整下一步。 |
| SECI 知识创造模型 | 把经验写出来、与他人交流、联系已有知识，再回到实践中验证理解。这里借用的是组织知识创造模型提供的思路。 |
| 人机协作与认知卸载 | 用 AI 辅助整理、比较和质疑，自己核查依据并形成判断。 |

这些借鉴对应八项设计原则。以人的成长为目标，允许跨主题和学科探索，让想法逐步成熟，保留自由结束的空间，给重要观点留下证据，主动建立知识关联，通过反思修正认识，由个人掌握数据与最终判断。

## 三种相互衔接的活动

- **思想探索。** 先记观察、直觉或困惑。用追问辨认真正的问题、关键假设和可能解释。探索可以暂停、恢复或结束，成果可以只是理解更清楚了一点。
- **个人知识成长。** 获取材料时记出处，用自己的话解释，和已有概念或案例连接，再通过复述、使用和反思检验理解。新的关联往往会带来新的问题。
- **研究与创造（GRC）。** 当你明确选择深入研究时，可以依次定义问题、梳理概念和理论、收集证据、比较解释、形成判断、检验论证、组织表达、审查并保存值得复用的内容。按学科和问题选择方法，允许返回前面的阶段。发布成果由你决定。

这些活动共用一个由个人维护的知识资产库。AI 协作可以在得到授权时提供上下文、比较和反证。保留可迁移的记录，换工具或模型时仍可继续思考。回看旧判断、辨认变化、带着新理解重新探索，开始下一轮学习。每轮可以只做其中几步。

## 怎么组织知识和证据

用相对稳定的标识保存八类可复用内容：灵感、问题、概念、理论、观点、证据、方法、成果。研究项目可以串起问题、证据和成果，反思记录可以保留你如何改变认识。每条重要记录可写日期、主题和来源，链接时注明关系以及它指向哪个版本。

| 记录 | 最小做法 |
| --- | --- |
| 问题 | 写目前想弄明白什么，附上触发它的观察和相关概念。 |
| 证据 | 写出处、具体定位和你实际看到了什么，说明它支持、反驳或限定哪一版观点。 |
| 观点 | 写判断、关键假设和当前状态，例如待核实、存在争议、已修正。修订时保留旧版和改变的理由。 |

来源、AI 摘要和个人判断都可以保存，分别写清内容和核查状态。一个来源可信，仍需检查它能否支持眼前的推论。判断发生变化时，可以核对原来的依据以及新发现影响的是哪一步。

## 怎样与 AI 分工

| 角色 | 可以交给 AI 的工作 | 你来决定 |
| --- | --- | --- |
| 思想伙伴 | 追问、联想、提出不同解释 | 想继续理解什么 |
| 知识助手 | 解释概念、组织材料、提示关联 | 是否理解，以及怎样应用 |
| 研究助手 | 建议检索方向、整理证据、比较方法 | 研究范围、方法和证据是否合适 |
| 批判性审查者 | 找反例、推理漏洞和可能偏见 | 哪些质疑足以改变判断 |
| 创造助手 | 整理结构、起草和修改 | 主张、表达和是否发布 |

默认由你发起，AI 可以提供建议。需要委托时，明确授权范围、可以访问的材料和交付要求。长期保存、重要观点的修改、删除和对外发布由你控制。这里描述的是协作方法，Grove 的实际读写权限见[插件详情](DETAIL.zh.md)。

## 不安装插件，怎么开始

1. **捕捉灵感。** 写下“为什么有些团队扩大后，决策变慢了？”补一句你在什么情况下观察到它。
2. **自由探索。** 列出几种解释，例如参与者增加、审批层级变多或决策权不清。可以自己推敲，也可以请 AI 追问。愿意的话，保留一个下次想问的问题。
3. **学习与关联。** 查清“协调成本”和“决策权”，用自己的话写下区别，各找一个例子，把这两条记录连回问题。
4. **按需开展研究。** 例如选取决策权限不同的团队做比较。记下可核对的来源和定位，并把它们连到判断。假设你起初认为团队规模最关键，后来发现授权方式能解释部分差异，就另存一版，写明反例和适用条件。这个例子用于演示记录方法。
5. **回顾与创造。** 需要交流时，把问题、证据和判断写成简短的分析。隔一段时间，可以问自己理解更深了什么、因何改过主意、哪个问题值得回去看。用这些答案决定下一次探索。

一份普通 Markdown 文件就够用。可以从四行开始：问题、当前理解、出处或待核查项、下一步。需要留下推理历史时，再加日期、证据关系和修订理由。
