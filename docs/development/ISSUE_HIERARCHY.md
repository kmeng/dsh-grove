# 任务分层

## 四层

| 层级 | 含义 | 拆分原则 |
| --- | --- | --- |
| **Epic** | 一个可交付的垂直切片 | 按用户能感知的价值切；验收标准写在 Epic 里 |
| **Story** | 能跑通一个闭环的用户故事 | 从入口到可验证产出，中途不靠人补位 |
| **DEV** | 开发子任务 | 只承担 Story 的一部分，必须挂在 Story 下 |
| **BUG** | 缺陷 | 先写根因，再修复；修复必须带回归测试 |

## 本仓库的轻量用法

Grove 是单包仓库，不强制 Epic：

- 小改动直接开 **Story**（一个闭环，如"让 bundle 在 0.2.2-rc.x 上被接收"）。
- 缺陷一律用 **BUG**，根因写进 issue 正文。
- 只有跨多个 Story 的能力（例如"支持中英双语素材"）才建 Epic，避免为仪式而仪式。

层级可以退，**验收标准不能退**：没有可检查的验收标准，说明还没拆清楚。

## 拆完自问

1. **闭环完整吗？** 做完这个，用户能不能走完"开始 → 产出"？不能就是拆大了。
2. **验收写得出吗？** 每条标准能不能用一条命令或一次目视证明？写不出就还没拆完。
3. **是垂直切片吗？** 尽量端到端可用，而不是横向把每个模块都铺一层。

## 反模式

- ❌ 一个 Story 覆盖"增删改查" → 拆成单个操作各自闭环。
- ❌ DEV 直接挂 Epic、跳过 Story → 丢掉验收单位。
- ❌ BUG 不写根因 → 同一个问题会以另一种形式回来。
- ❌ 为凑 PR 数量把一次改动切成几个不能独立验证的 PR。

## 与机检的对应

| 原则 | 可机检落点 | 在哪 |
| --- | --- | --- |
| BUG 必须带回归测试 | 修复提交同时含测试变更 | 评审 + `git show --stat` |
| 关闭必须有证据 | PR/issue 里的实测输出 | PR 模板 |
| Story 验收标准逐条有证据 | 验收对照表 | PR 模板 |
