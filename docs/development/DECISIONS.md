## D-006 · Grove 增加 Web 客户端与同源 HTTP 路由

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：Host-only 时左侧没有入口，配置 vault 只能靠环境变量；用户要求安装后在菜单里看到 Grove，并能直接上手。
- **选项**：① 静态说明页，不读数据，冷启动价值低；② Typert Remote 服务，依赖面与验证成本更高；③ 同源 HTTP 路由 + 手写客户端，参照 `article-studio` 的形态。
- **决定**：③。`client.js` 注册 `sidebar.panellist` 与 `main`；新增 `GET /status`、`POST /config`、`POST /capture`；vault 路径经 `configEditor` 写入 profile；页面只返回元数据。
- **理由**：无需构建工具，与现有插件形态一致；配置走宿主机制，不手改 profile 文件；页面写入由用户点击触发，不改变「AI 草稿要终端确认」的边界。
- **风险与兜底**：保存配置会重启插件，页面用轮询等待；客户端接口随 DSH 版本变化；替换已安装包后需要重启才能加载新客户端。未配置时 `status` 仍可用，保存失败回退到手动路径或 `GROVE_VAULT`。

## D-005 · 首次发布依赖 npm 的 processing 队列，不重试

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：新包首次 `npm publish` 会先出现 `0.0.0-stage` 占位版本，并提示 "being processed"，真实版本约三分钟后才出现；此时重复发布同一版本会报 `Cannot publish over previously staged version`。
- **决定**：发布后轮询 `/dsh-grove/<version>` 直到 200，不重复发布；版本一旦被占用就升版本，不复用。
- **理由**：这条报错容易被当成失败，重试只会浪费；占位版本与 staged 状态都不是可回滚的错误。
- **风险**：占位版本会短暂出现在版本列表里，`latest` 在真实版本出现前指向它；发布后核对 `npm view dsh-grove dist-tags` 即可确认。

## D-004 · 双语素材用语言后缀区分

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：头图与社交预览最初只有一个无后缀文件名，实际内容是中文。英文读者拿到图后不知道该用哪张，也没法区分。
- **选项**：① 一个文件内中英混排；② 两种语言各一份，文件名带 `.zh` / `.en`。
- **决定**：②。`build.sh` 一次产出全部语言版本，测试断言两份都存在且尺寸正确。
- **理由**：发布会同时面向中英文读者，同图混排会让不认识的文字变成噪声。
- **风险**：文件数量翻倍；靠测试约束，避免只更新一半。

## D-003 · 品牌资产不进 npm 包，`icon.svg` 与主标志字节一致

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：品牌资产有十几张 PNG、几百 KB；插件实际只需要一张 36 视框的 `icon.svg`。而市场瓦片是 GitHub raw 提供的，不走 npm。
- **决定**：`brand/` 不进 `files`；根目录 `icon.svg` 作为发布用图标，必须与 `brand/mark.svg` 字节一致，由测试保证。
- **理由**：安装包保持 10 KB 级别；图标只有一个来源，避免两处漂移。
- **风险**：两个文件重复；字节一致的断言让漂移立刻被发现。

## D-002 · 宿主包同时声明在 peer 与 dev

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：`src/plugin.js` 静态 `import { defineTool } from '@deepseek-ai/dsh-tools'`。最初把它从 `peerDependencies` 里删掉，只留 `devDependencies`。
- **问题**：`link:` 目录安装靠祖先 `package.json` 的 `peerDependencies` 名字启用安装侧的解析拦截；删掉 peer 后会解析到 checkout 里的旧版本，或直接找不到。
- **决定**：两边都声明，都是范围 `>=0.2.2-rc.1 <0.3.0`。宿主文档 `docs/user/develop/basic/publish.md` 同样要求。
- **风险**：profile 的 pnpm 配置 `autoInstallPeers: false`，不会因此多装一份。

## D-001 · `engines.dsh` 用范围，不用精确版本

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：最初的 `engines.dsh` 是精确的 `0.2.2-rc.1`，在 `0.2.2-rc.3` 上整个 bundle 被判不兼容并跳过，装上了却一行都不加载。
- **原因**：dsh 只要看到 `engines.dsh` 就只按它判定，`peerDependencies` 被忽略。
- **决定**：`>=0.2.2-rc.1 <0.3.0`，并在 `test/manifest.test.js` 里断言"不是精确版本、覆盖当前版本线"。
- **风险**：`0.3.0` 之后的行为未验证；范围本身已排除。

## D-009 · 0.2.0 到 0.5.0 的数据升级与恢复

- **日期** 2026-11-14
- **状态** 已定案
- **兼容基线** 保留已有 `Grove/<id>.v<n>.md`、YAML 字段、草稿文件、ID 和历史版本。当前已知旧格式由新版本直接读取。新能力在兼容格式之外使用独立的新增记录。应用版本与存储格式版本各自管理。
- **预检与备份** 升级前暂停所有写入。对整个 `Grove` 目录建立独立快照，包含隐藏草稿、旧版本及无法解析的文件。核对原目录与快照的文件集合和 SHA-256。预检遇到链接、特殊文件、无法读取项或复制期间变化即失败。快照通过验证才写出完成标记。
- **未来的格式转换** 只有明确的格式版本转换才运行迁移。读取源格式，校验受支持的转换，备份后在临时目标生成结果。对数量、版本 ID、引用及文件摘要做验证，再发布到独立目录并切换配置。失败保留原目录和可验证备份。重复启动继续使用已验证结果，遇到未知格式阻止写入。
- **恢复** 有效快照恢复到独立空目录，验证后人工切换。保留升级后的目录供对账，避免覆盖升级期间的新数据。回退到 0.2.0 使用旧格式快照，新版本生成的资料和报告保留在升级后的目录。
- **验收** 用包含多版本笔记、证据和隐藏草稿的 0.2.0 测试数据，验证升级前后逐字节一致、损坏快照拒绝恢复、恢复目标已存在时放弃写入。
