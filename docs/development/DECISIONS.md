## D-006 · Grove 增加 Web 客户端与同源 HTTP 路由

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：Host-only 时左侧没有入口，配置 vault 只能靠环境变量；用户要求安装后在菜单里看到 Grove，并能直接上手。
- **选项**：① 静态说明页，不读数据，冷启动价值低；② Typert Remote 服务，依赖面与验证成本更高；③ 同源 HTTP 路由 + 手写客户端，参照 `article-studio` 的形态。
- **决定**：③。`client.js` 注册 `sidebar.panellist` 与 `main`；新增 `GET /status`、`POST /config`、`POST /capture`；vault 路径经 `configEditor` 写入 profile；页面只返回元数据。
- **理由**：无需构建工具，与现有插件形态一致；配置走宿主机制，不手改 profile 文件；页面写入由用户点击触发，不改变「AI 草稿要终端确认」的边界。
- **风险与兜底**：保存配置会重启插件，页面用轮询等待；客户端接口随 DSH 版本变化；替换已安装包后需要重启才能加载新客户端。未配置时 `status` 仍可用，保存失败回退到手动路径或 `GROVE_VAULT`。

## D-005 · 首次发布依赖 npm 的 processing 队列，不重试

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：新包首次 `npm publish` 会先出现 `0.0.0-stage` 占位版本，并提示 "being processed"，真实版本约三分钟后才出现；此时重复发布同一版本会报 `Cannot publish over previously staged version`。
- **决定**：发布后轮询 `/dsh-grove/<version>` 直到 200，不重复发布；版本一旦被占用就升版本，不复用。
- **理由**：这条报错容易被当成失败，重试只会浪费；占位版本与 staged 状态都不是可回滚的错误。
- **风险**：占位版本会短暂出现在版本列表里，`latest` 在真实版本出现前指向它；发布后核对 `npm view dsh-grove dist-tags` 即可确认。

## D-004 · 双语素材用语言后缀区分

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：头图与社交预览最初只有一个无后缀文件名，实际内容是中文。英文读者拿到图后不知道该用哪张，也没法区分。
- **选项**：① 一个文件内中英混排；② 两种语言各一份，文件名带 `.zh` / `.en`。
- **决定**：②。`build.sh` 一次产出全部语言版本，测试断言两份都存在且尺寸正确。
- **理由**：发布会同时面向中英文读者，同图混排会让不认识的文字变成噪声。
- **风险**：文件数量翻倍；靠测试约束，避免只更新一半。

## D-003 · 品牌资产不进 npm 包，`icon.svg` 与主标志字节一致

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：品牌资产有十几张 PNG、几百 KB；插件实际只需要一张 36 视框的 `icon.svg`。而市场瓦片是 GitHub raw 提供的，不走 npm。
- **决定**：`brand/` 不进 `files`；根目录 `icon.svg` 作为发布用图标，必须与 `brand/mark.svg` 字节一致，由测试保证。
- **理由**：安装包保持 10 KB 级别；图标只有一个来源，避免两处漂移。
- **风险**：两个文件重复；字节一致的断言让漂移立刻被发现。

## D-002 · 宿主包同时声明在 peer 与 dev

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：`src/plugin.js` 静态 `import { defineTool } from '@deepseek-ai/dsh-tools'`。最初把它从 `peerDependencies` 里删掉，只留 `devDependencies`。
- **问题**：`link:` 目录安装靠祖先 `package.json` 的 `peerDependencies` 名字启用安装侧的解析拦截；删掉 peer 后会解析到 checkout 里的旧版本，或直接找不到。
- **决定**：两边都声明，都是范围 `>=0.2.2-rc.1 <0.3.0`。宿主文档 `docs/user/develop/basic/publish.md` 同样要求。
- **风险**：profile 的 pnpm 配置 `autoInstallPeers: false`，不会因此多装一份。

## D-001 · `engines.dsh` 用范围，不用精确版本

- **日期**：2026-11-14
- **状态**：已定案
- **背景**：最初的 `engines.dsh` 是精确的 `0.2.2-rc.1`，在 `0.2.2-rc.3` 上整个 bundle 被判不兼容并跳过，装上了却一行都不加载。
- **原因**：dsh 只要看到 `engines.dsh` 就只按它判定，`peerDependencies` 被忽略。
- **决定**：`>=0.2.2-rc.1 <0.3.0`，并在 `test/manifest.test.js` 里断言"不是精确版本、覆盖当前版本线"。
- **风险**：`0.3.0` 之后的行为未验证；范围本身已排除。

## D-012 · 内置深度研究的执行与存储

- **日期** 2026-11-15
- **状态** 已定案
- **工作流** 默认实现由知林维护。输入为问题、可选方向和指定版本的灵感或知识背景。流程依次拆题、收集资料、核验关键结论、按缺口补查、生成 Markdown。编排通过 `run({ model, retrieve, checkpoint, initial })` 接收依赖。宿主路由负责装配和权限边界，模型负责结构化计划、核验和摘要，检索接口负责返回有来源的原文，Vault 负责版本与持久化。
- **检索范围** 默认检索当前话题已导入的资料。配置公开网页检索后，仅把研究查询交给搜索服务。首个网页检索适配器为 Tavily，凭据通过宿主环境变量提供。采用实际返回的网页原文。未配置联网服务且缺少库内材料时，报告明确标出证据不足。支持与分歧状态至少需要来自两个不同来源的可匹配原文摘录。重复发表与证据解释仍须人工复核。
- **进度与恢复** 用真实检查点展示拆题、搜集、待补查事项和核验结果。运行记录保存于 `Grove/.research-runs/<id>.json`，当前格式版本为 1。重启后，从已落盘的步骤继续。报告使用运行 ID 作为稳定 ID，最终保存中断时重试沿用同一份报告。工作流留档随 Vault 备份保留。
- **报告** 完成后以 Markdown 保存待审核草稿。报告用稳定话题 ID 检索，保留研究版本与库内证据版本；证据回到固定版本和原文位置。草稿确认后产生新版本，方可用作知识或作品的依据。升级沿用已有 Markdown、YAML 与版本路径，旧报告无需转换。

## D-016 · HTTP、Vault 与联网补查的边界

- **日期** 2026-11-15

- **HTTP** 沿用 dsh 宿主的登录和来源校验。读写使用独立路由，以适配宿主按路径配置请求体模式的接口。写入流式读取 JSON，解码前累计上限为 1 MiB，业务层继续执行笔记和导入各自的限制。

## D-017 · 用公开网页链接发起研究

- **日期** 2026-11-15
- **状态** 已定案
- **联网入口** 模型仍是深度研究必需项。研究输入带有公开网页链接时，直接读取网页，不调用 Tavily。没有链接时，可沿用显式启用且配置好的 Tavily 自动搜索。
- **边界** 读取仅访问标准 HTTP(S) 端口上的公网 IPv4，连接固定到经过校验的解析地址，保持原域名的 TLS 校验。拒绝带凭据的链接、跨域跳转和超限响应。用公开链接运行时，补查只查询库内资料。
- **失败与恢复** 链接无法读取时保留失败状态并提示检查链接。报告引用实际读取的网页，来源不足时继续标记证据不足。

## D-018 · 优先复用 dsh 的联网能力

- **日期** 2026-11-18
- **状态** 已定案
- **宿主契约** 可用时通过可选的 `ctx.web` 服务，调用宿主已选择的联网搜索和凭据。没有宿主搜索时，可退回已配置的 Tavily；用户直接给公开链接时仍可跳过搜索。沿用既有的宿主版本范围和运行时能力检测。
- **网页读取边界** 优先使用宿主配置的 DeepSeek 远程网页读取。宿主的默认本机 HTTP 读取可访问内网，Grove 不把研究自动发现的 URL 交给它，而是沿用 D-017 的公网限定读取。读取失败的搜索结果仅在有文本摘要时提供给核验，报告仍须引用实际取得的材料。
- **日期与隐私** 用客户端时区给模型提供当前日期，处理相对时间。宿主联网拆题只使用用户在本轮发送的内容及日期；私有附件只用于核验和库内补查，不加入公开补查查询。

## D-019 · 知识库每日整理

- **日期** 2026-11-22
- **状态** 已定案
- **来源** 知识条目引用收藏时的确切报告版本。展开时读取该报告，原课题由报告上的研究关联确定。历史条目仍可读取自己的正文，报告文件缺失时显示提示和留存正文。
- **索引** 自动标签来自标题和正文的本地分词。关联按共同标签和报告来源或原课题评分。每条知识最多展示五个标签和五条相关知识。
- **存储** 在当前 vault 的 `Grove/.knowledge-index.json` 保存可重建的索引，包括格式版本、成功整理日期和按知识 ID 记录的笔记版本、标签与关联 ID。更新索引通过同目录临时文件和原子替换发布。知识 Markdown 和报告版本历史保留原样。
- **调度与恢复** DSH 宿主启动后检查当前 vault，运行期间每分钟检查是否需要整理。按宿主本地日期记录成功，当天已有成功记录就跳过。宿主关闭期间错过的整理会在下次启动时补跑当前日期。失败时保留上次成功的索引，下一次检查可以重试。


## D-020 · 知识概念、缩写与索引升级

- **日期** 2026-11-22
- **状态** 已定案
- **标签** 优先识别标题与正文里的完整概念，保留缩写的原大小写。别名各自可以用来筛选条目，同一概念只贡献一次关联分。每条知识最多展示五个标签。
- **迁移** 索引使用 schema 2。读取旧索引可维持界面，宿主发现旧 schema 时即使当天已经运行过也会重建。成功后原子替换旧索引，失败可重试。知识正文和报告版本仍由原有笔记保存。

## D-021 · 作品对话、成稿与本地配图

- **日期** 2026-11-22
- **状态** 已定案
- **草稿** 对话、主题、提纲、小节正文及配图信息以 schema 1 JSON 存在 vault 的 `Grove/.work-drafts/`。更新使用临时文件和原子替换。当前宿主对同一草稿串行处理写入，同一份草稿的请求携带版本号，过期请求返回冲突。
- **成稿** 确认保存时创建现有 `output` 类型的 Markdown，沿用作品版本和确切引用。成稿使用草稿 ID，读回时可识别重试产生的同一份作品。草稿在作品列表中退出待写列表，已保存作品仍可读取和修订。
- **配图** 用户上传 PNG、JPEG 或 WebP，单张最大 4 MiB。文件按内容摘要命名，存于 `Grove/work-media/`，正文使用相对路径。图片及草稿随 Grove 目录一起备份。图片由应用同源路由提供，配图提示词由文本模型生成。
- **模型** 使用当前 profile 的默认文本模型。只在用户提交方向或请求配图提示时调用。创作可引用用户选定的知识或已确认报告版本，模型请求失败时已保存的内容可继续使用。
