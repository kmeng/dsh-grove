# 2026-11-22 · v0.7.5 作品工作台发布与复盘

## 做完

- 作品工作台的会话操作集中在左侧，右侧是固定标题与独立滚动的只读预览。主题、提纲和小节各有对话记录，模型生成候选，经用户确认才写入正文。写作模型与图片模型可各自配置。成稿按版本收录知识库。 [功能 PR #283](https://github.com/kmeng/dsh-grove/pull/283)
- `0.7.5` 发布工作流全部通过，公开 npm `latest` 已指向该版本，安装包通过 SHA-512 校验。保留最近十个 Release，已移除最旧 Release 条目，v0.6.6 tag 和包仍可查询。 [发布](https://github.com/kmeng/dsh-grove/releases/tag/v0.7.5) · [工作流](https://github.com/kmeng/dsh-grove/actions/runs/45026732136)

## 卡住

- 外部图像接口用模拟响应验收，本次环境未配置图片服务凭据。带出处和单位的数据图表、图片上传、提示词路径各自可用。
- 「为本节补资料」能发起研究。确认报告后仍要回草稿的本节素材手动检索并采用，研究和草稿之间缺少直接返回入口。

## 下一步

| 优先级 | 评审发现 | 下一步验收 |
| --- | --- | --- |
| P1 · 产品 | 输出确认后有确切版本，保住了从灵感到成稿、再回知识库的链路。补资料仍需跨页找回草稿，是当前最容易中断创作的地方。 | 从任意小节发起研究，确认报告后返回原小节并选入该版本。正文、提纲和已采用的引用均保持原样。 |
| P1 · 数据 | 逐修订原子写入使候选和确认可追溯，也会重复保存完整快照。现有单个快照 2 MiB 上限与全目录扫描会约束长草稿和很多作品的 vault。 | 为长篇、多轮和并发场景测量耗时、磁盘增长和失败恢复，再引入分段记录或检查点。历史仍能安全读回。 |
| P2 · 技术 | 模型与配图已有独立模块。工作台仍和其他页面共处约 3,000 行的单个客户端入口，草稿命令集中在同一个服务处分派。 | 增加创作页面的组件边界和作用域命令测试，先保证现有界面和接口继续可用，再逐步调整文件结构。 |
| P2 · 图片 | 柱状图依赖明确的数据、单位和出处，生成产物能回看。外部图片首版只支持 Base64 响应，图表源数据暂未作为可重编的独立资产。 | 选定一个实际图片服务验证生成、失败和回退；用同一组带出处的数据修改图例并重新生成。 |
